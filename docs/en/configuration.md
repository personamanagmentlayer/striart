# Configuration

> [Documentation](README.md) · Configuration

The config is loaded by cosmiconfig: `striart.config.mjs` (generated by
`striart init`, recommended — explicit ESM, works even if the target repo is
CommonJS), but also `striart.config.js`, `.striartrc.json`,
`.striartrc.yaml`… It is validated at load time: an invalid value is refused
with its reason (`CONFIG_INVALID` — only the faulty **key** is quoted, never
its value, which could carry a secret), never silently degraded. Nested
settings (`tokens`, `orchestration`, `acpAgent`, `pty`, `terminal`, `mcp`…)
**refuse an unknown key**: a typo on a security setting must not make you
believe a relaxation or a ceiling is active.

> **A `.mjs`/`.js` config is executed code** (see
> [SECURITY.md](../../SECURITY.md)): never load a third party's without
> reading it. Some settings that widen a trust therefore live outside the
> repository — see [User configuration](#user-configuration-outside-the-repository).

Everything has a sensible default — the minimal config fits in three lines:

```js
export default {
  unknownConfigKeys: 'error',     // unknown top-level key: 'error' (default) = CONFIG_INVALID | 'warn' (relaxation)
  testCommand: 'npm test',   // the Test Gate command — the only really load-bearing setting
  targetBranch: 'main',      // branch to merge into — 'master', 'dev'… work too
};
```

**Guiding principle**: every behavior with defensible choices is a validated
key with a **safe default**; relaxing a protection is explicit, logged, and
shown by `striart doctor` (a dedicated line and the "relaxed protections"
summary).

## Unknown keys: `unknownConfigKeys`

A top-level key Striart does not know (`testComand`, `commitPolcy`…) is
**refused** at load time: `CONFIG_INVALID`, sub-code `UNKNOWN_KEY`, with the
key and the closest suggestion ("did you mean `testCommand`?"). Why: a typo on
a security setting would leave the intended protection at its default with
nobody noticing. Only `$schema` is admitted without a validator.
`unknownConfigKeys: 'warn'` is the explicit relaxation: the key is ignored,
logged at every load, and `striart doctor` lists it among the relaxed
protections. Any value other than `'error'` or `'warn'` is itself refused
(`CONFIG_INVALID`, key `unknownConfigKeys`).

## `secretPatterns` — secrets in clones

**gitignore** syntax: a pattern with no `/` names the file at any depth; a
leading or inner `/` anchors it at the root; a trailing `/` only names a
directory; `**`, `*`, `?` and `[...]` as in `.gitignore`. **Tracked** files
are removed from a clone's worktree by sparse-checkout, according to the set
**git itself** computes (`ls-files --exclude`) — never an approximate
reimplementation; the history is scanned before any clone (non-ASCII names and
renames included): a path that ever existed under one of these patterns
refuses the clone (`HISTORICAL_SECRETS_FOUND`). **Refused**
(`SECRET_PATTERN_INVALID`): the `!` negation, the `#` comment, the empty
pattern and the newline. `secretPatterns: []` is an explicit **relaxation**
(no exclusion, no scan), shown by `striart doctor`.

## The Router/Merger LLM

The Router (file prediction) and the Merger (semantic merge) go exclusively
through the provider layer `src/llm.js`. **Local Ollama is the default**
(zero cost, zero network), but any LLM can be used:

```js
llm: { provider: 'ollama' | 'openai' | 'anthropic' | 'azure', model, baseUrl?, apiKeyEnv?, apiVersion? }
// llm: { provider: 'openai', model: 'gpt-5.4-mini' },                      // key via OPENAI_API_KEY
// llm: { provider: 'anthropic', model: 'claude-haiku-5-5' },               // key via ANTHROPIC_API_KEY
// llm: { provider: 'openai', model: 'openai/gpt-oss-120b', baseUrl: 'https://api.groq.com/openai/v1', apiKeyEnv: 'GROQ_API_KEY' },
// llm: { provider: 'azure', model: '<deployment>', baseUrl: 'https://<resource>.openai.azure.com' },
// llm: { provider: 'openai', model: 'x', baseUrl: 'http://localhost:1234/v1' }, // LM Studio, vLLM, llama.cpp...
```

**Every major provider is supported** — natively (`ollama`, `openai`,
`anthropic`, `azure`) or through its OpenAI-compatible endpoint: Gemini,
Mistral, Groq, DeepSeek, xAI, Together, Fireworks, OpenRouter, Perplexity,
Cohere, and on-premise LM Studio, vLLM, llama.cpp, TGI. AWS Bedrock and
Google Vertex (SigV4/OAuth auth) go through a LiteLLM proxy. The
**[.env.example](../../.env.example)** documents the exact config of each one.

API keys are **never** in the config: only the name of an environment
variable (`apiKeyEnv`), loaded from the shell or a `.env` at the **repo
root** (a variable already set in the shell wins). `striart init` and
`striart doctor` check the key is present (or that Ollama answers) — a
warning, never blocking.

The root `.env` is **untrusted** data (a cloned repository can ship one):
only the variables of an **allow-list** are applied — the `*_API_KEY` names,
`STRIART_LANG`/`THEME`/`ASCII`/`NO_ANIMATION`, `SLACK_WEBHOOK_URL`,
`DISCORD_WEBHOOK_URL`, `INTERNAL_WEBHOOK_URL`, `AZURE_OPENAI_ENDPOINT` — and a
deny-list (`NODE_*`, `LD_*`, `DYLD_*`, `PATH*`, `HOME`, `GIT_*`, `*_PROXY`,
`STRIART_NATIVE_BIN`, `STRIART_CONFIG_HOME`…) always wins. Discarded
variables are named on stderr. To admit others, use the `env.allow` list of
the [user configuration](#user-configuration-outside-the-repository) — the
deny-list stays non-relaxable.

Two guards protect the API key from a hostile repository, which would supply
`apiKeyEnv: 'GITHUB_TOKEN'` and a `baseUrl` of its own: `apiKeyEnv` must have
the shape of a key (UPPERCASE ending in `_API_KEY`, `_KEY` or `_TOKEN`) and
not designate an infrastructure secret (`GITHUB_*`, `NPM_*`, `AWS_*`,
`SSH_*`, `DOCKER_*`, `STRIART_*`…); the key only leaves over HTTPS (loopback
is exempt). Refusal: `LLM_CONFIG_INVALID`. Two explicit relaxations, shown by
`doctor`: `llm.allowAnyApiKeyEnv: true` and `llm.allowInsecureTransport:
true`. A host that is not the provider's is logged once (legitimate proxy or
hijack).

**`llm.allowInsecureTransport` is no longer enough for a remote host over
HTTP.** Every outgoing call now goes through the
[network layer](#enterprise-network-network): it requires HTTPS outside the
loopback, with or without an API key, and lifts that requirement only for the
hosts declared in `network.allowInsecureHosts` of the **user configuration**
(never in the repository). A remote `ollamaHost` in `http://` is therefore
refused (`NET_INSECURE_TRANSPORT`) until its host is listed there;
`http://localhost:11434` (the default) stays free.

**JSON output wrapped in a markdown block.** Providers without a native JSON
mode (Anthropic) readily wrap their answer in a code block (`json` tag). For
every call that expects JSON (the Router and the judge of a `race`), Striart
unwraps the block **before** `transform` (the role's own validation), and
**only** if it covers the whole answer — a single block, nothing around it
(`unwrapJsonResponse`, `src/llm.js`); any other shape is rejected as before.
The unwrapping also applies to answers read back from the result cache.

### `llmRoles` — one LLM per role

`llmRoles: { router, merger, memory, judge }` gives each role its own model;
each entry is an `llm` specification (same fields) or `null` (= the global
`llm` block, or Ollama). A cheap local model for the Router and a strong
model for the Merger, for instance. `judge` is the LLM that ranks a `race`
(`pick: judge`). Only these four roles exist (unknown key refused); the
`review` reviewers are agents, not Striart LLM roles.

### `llmResilience` — retries, backoff and circuit breaker

Every Striart LLM call is retried with an **exponential backoff with full
jitter** and honors `Retry-After`; a per-provider **circuit breaker** avoids
hammering a failing service. Only transient errors are retried (network,
timeout, 408, 409, 425, 429, 5xx except 501/505); a configuration or request
error (400, 401, 403, 404, 422) never is — replaying it would burn time and
tokens for the same refusal.

```js
llmResilience: {
  backoff: {
    baseMs: 500,            // 1 to 60,000 — starting wait (drawn in [0, min(maxMs, baseMs·2^n)])
    maxMs: 20000,           // 1 to 600,000 — cap of the wait
    maxRetryAfterMs: 60000, // 0 to 3,600,000 — beyond it, no waiting: plain failure
  },
  breaker: {
    enabled: true,          // false = relaxation (shown by doctor, "tokens" line)
    failureThreshold: 5,    // 1 to 1000 — consecutive retryable failures before opening
    cooldownMs: 30000,      // 100 to 3,600,000 — open duration, then ONE probe call
  },
}
```

The breaker lives in process memory (a long `watch` or dashboard benefits, a
one-shot CLI starts clean).

### Overridable prompts

`prompts.router` and `prompts.merger` **fully** replace the default prompts
(`null` → default) — useful, for example, to rewrite them in English when the
local model is more reliable in English. Placeholders are **mandatory and
validated at load**:

- router: `{{task}}` + `{{files}}`;
- merger: `{{file}}` + `{{base}}` + `{{ours}}` + `{{theirs}}` +
  `{{feedback}}` (the post-gate retry injects the failure log there).

## Tokens: accounting, ceilings and savings (`tokens`)

Striart records **every LLM call** (Router, Merger, Memory, judge, review)
and every agent session in an append-only ledger `.striart/usage/`
(`striart usage`), never writing a prompt, a response or a key there. The
`tokens` block tunes this ledger, the **ceilings** and the optimizations. It
is a partial object deep-merged with these defaults; an unknown key is
refused.

```js
tokens: {
  accounting: true,            // false = relaxation: no record at all, blind budgets
  onAccountingError: 'warn',   // 'warn' | 'fail' — if recording or re-reading the totals fails (see below)
  retentionDays: 90,           // 1 to 3650 — ledger retention (applied by striart prune)
  pricing: {},                 // NO hard-coded price — see below
  pricingStaleAfterDays: 90,   // 1 to 3650 — age beyond which doctor flags a stale price
  estimator: { safetyFactor: 1.15, charsPerToken: 3 },  // margin ≥ 1 (≤ 5); 1 to 8 chars/token

  budgets: {                   // OPT-IN ceilings: null = no ceiling
    enforcement: 'hard',       // 'hard': refuses; 'alert-only': relaxation, only alerts
    warnAtRatio: 0.8,          // fraction of a ceiling that raises the alert
    perCall:  { maxInputTokens: null, maxOutputTokens: null, maxTokens: null, maxCostUsd: null },
    perTask:  { maxTokens: null, maxCostUsd: null },
    perAgent: { maxTokens: null, maxCostUsd: null },
    perDay:   { maxTokens: null, maxCostUsd: null },   // UTC day
    global:   { maxTokens: null, maxCostUsd: null },   // over the ledger retention
  },
  alerts: {                    // absolute thresholds (alert only) while no ceiling is set
    callInputTokens: 150000, taskTokens: 20000000, dayTokens: 100000000,   // null = disabled
  },

  router: {                        // see "tokens.router" below
    onBudgetExceeded: 'serialize',  // ceiling reached: 'serialize' (cautious) | 'fail'
    onTreeTruncated: 'serialize',   // more than tree.maxFiles files: 'serialize' | 'predict' (relaxation)
    tree: { maxFiles: 50000, mode: 'auto',        // 'auto' | 'full' | 'compact'; maxFiles: 100 to 10,000,000
            maxTreeTokens: 6000, importExpansion: true,
            exclude: [ /* node_modules, dist, build, coverage, vendor, *.min.js, *.map, images, archives… */ ] },
    preset: 'balanced',             // 'balanced' (default) | 'recall' | 'legacy'
    prompt: 'v3',                   // 'v3' | 'legacy'
    map: { mode: 'candidates', candidates: 40 },          // 'candidates' | 'off'; 1 to 500
    retrieval: { enabled: true, bilingual: true },
    expansion: { imports: 'off', depth: 1, tests: true, siblings: false,
                 contracts: false, coChange: false, maxAdded: 6 },   // imports: 'off' | 'importees' | 'importers' | 'both'; maxAdded: 0 to 50
    minFileConfidence: 0.5,         // 0 to 1 — LLM files below this are dropped (0 = keep all)
    maxFiles: 6,                    // 1 to 50 — files kept from the LLM's answer
    vague: { enabled: true, minConfidence: 0.3, maxFiles: null, verbs: false },
    sharedFiles: { mode: 'exclude', patterns: [ /* CHANGELOG*, README*, CONTRIBUTING*, docs/**, roadmap/**, package.json, lockfiles… */ ] },
    history: { limit: 400 },        // 10 to 5000 commits re-read (co-change)
    maxScanFiles: 5000,             // 100 to 1,000,000 — above this, file contents are not read
  },
  merger: { mode: 'auto',          // 'auto' (by region above the threshold) | 'full' | 'hunk'
            hunkThresholdChars: 16000, contextLines: 5, maxWindowTokens: 30000 },
  memory: { maxEntryChars: 1200, maxTotalChars: 12000, diffMaxChars: 8000, dedupe: true },
  promptCache: { enabled: true, ttl: '5m', minPrefixTokens: 1024 },   // Anthropic: cache_control
  cache: { enabled: true, roles: ['router', 'memory'], ttlMs: 600000, maxEntries: 200 },
  instructions: { mode: 'full' },  // 'full' | 'compact': template of the injected instructions
}
```

- **Prices are declared, never shipped**: a price changes without notice and
  depends on the contract. `pricing` maps `provider:model` (or `model`) to
  `{ inputPerMTok, outputPerMTok, cacheReadPerMTok?, cacheWritePerMTok?, asOf }`;
  `asOf` (YYYY-MM-DD) is **mandatory** — an undated price is worth nothing —
  and `doctor` flags prices older than `pricingStaleAfterDays`. The only
  exception: a local Ollama model is counted at 0 USD.
- **A set ceiling is enforced, fail closed.** Exceeded, the LLM call is
  refused *before* anything is sent (`TOKEN_BUDGET_EXCEEDED`, exit 3) and an
  agent session is stopped cleanly (`BUDGET_EXCEEDED`, clone kept). A
  **cost** ceiling with no price declared for the model cannot be enforced:
  the call is refused (`TOKEN_PRICE_MISSING`). A budget refusal is not an LLM
  failure: it does not count toward manual mode. `perCall` bounds a call's
  estimated input and the output passed to the provider; an output cut by
  `maxOutputTokens` is a **plain error**, never a silently truncated text
  mistaken for a complete merge.
- **A failing accounting is never silent.** If writing the usage ledger or
  re-reading the budget totals fails (disk, permissions, antivirus), the log
  receives a warning with the stable code `TOKEN_ACCOUNTING_FAILED` (budgets
  are then blind for that call). `onAccountingError: 'warn'` (default) never
  loses the answer of a call already paid; `'fail'` refuses instead of going
  forward blind: the LLM call whose recording fails is rejected and a session
  whose totals are unreadable does not start (`TOKEN_ACCOUNTING_FAILED`,
  failure — exit 1). Asynchronous session streams (alerts, final flush) only
  log.
- **Relaxations** — `accounting: false`, `enforcement: 'alert-only'` with a
  ceiling set, `'merger'` in `cache.roles`, `router.onTreeTruncated:
  'predict'`, an explicitly set `router.sharedFiles.mode: 'exclude'`,
  `llmResilience.breaker.enabled: false` — are shown by `doctor`.
  Tightening (setting a ceiling, `compact`) is not a relaxation.
- **Optimizations**: the Merger submits only the **conflicting regions** with
  their context when a file exceeds `hunkThresholdChars`, and refuses
  (`MERGE_WINDOW_EXCEEDED`, human ticket) a conflict larger than
  `maxWindowTokens` rather than truncating; the Router tree is ranked by
  relevance and summarized by folder if it overflows `maxTreeTokens` (a
  truncation at `maxFiles` is *declared*, never silent); the Memory Layer
  de-duplicates its bullets. The **result cache** (`.striart/usage/cache/`)
  only applies to outputs validated downstream (Router → collisions,
  Memory → advisory); the judge and the review, which arbitrate, **never**
  enter it.
- An agent must not be able to disable this guardrail from the repo config it
  modifies: `tokens` lives in the repo config, which the protected-paths
  guard protects (a merge that changes it is refused). Setting the ceiling in
  the *user config* is not yet possible (see the roadmap).

### `tokens.router` — Router reliability

The Router is a **coarse filter, not a guarantee**: it predicts the files a task
will touch so as to serialize agents that would overlap, but a wrong prediction is
caught later by the semantic merge and the Test Gate (see
[Architecture](architecture.md#what-the-router-and-the-semantic-merge-are-worth--measurements-of-2026-10-26)).
The eleven keys added by the reliability batch (`preset`, `prompt`, `map`,
`retrieval`, `expansion`, `minFileConfidence`, `maxFiles`, `vague`, `sharedFiles`,
`history`, `maxScanFiles`) join `onBudgetExceeded`, `onTreeTruncated` and `tree`.
Each is validated (bounds above) and **measured** by `npm run bench:router`; an
unknown key is refused.

**What the Router does, in order.** (1) It receives the tree of tracked files
(filtered, ranked, compacted according to `tree`); (2) a **deterministic lexical
retrieval** (BM25 over paths, symbols and the first doc line, with a French →
English bridge when `retrieval.bilingual`) ranks the files closest to the request;
the **map** of the best `map.candidates` (symbols and doc line) is added to the
prompt; (3) the LLM answers, with the `v3` template, a **confidence per file**, a
scope (`narrow`/`broad`) and an overall confidence; (4) files below
`minFileConfidence` are dropped, at most `maxFiles` are kept; (5) a **vague-task
detection** (`vague`) can replace the whole prediction with the `**` sentinel; (6)
a **deterministic expansion** (`expansion`) adds, from repository facts and never
from a second LLM opinion, the tests, importers, twins and co-changed files; (7)
**bookkeeping files** (`sharedFiles`) are removed from collision detection. A
failure stays a failure (`ROUTER_FAILED`): never a misleading empty array.

**Presets.** `preset` sets a coherent bundle; explicit keys win over it. `legacy`
reproduces the behaviour from before the batch exactly (historical prompt, no map
or retrieval, `maxFiles: 50`, no vague-task detection, bookkeeping files kept).
`recall` pushes recall (no confidence threshold, expansion through importers,
twins, contracts and co-change, `vague.minConfidence: 0.4`, `vague.maxFiles: 10`).
`balanced` (default) matches the values in the reference above.

Reading: raising recall costs waiting. A "needless alert" is a pair of tasks with
no real overlap that the Router serializes anyway; a missed overlap is the
dangerous case (the Merger catches it later, at a cost). The `recall` preset
serializes one task in three to one in two: it is only reasonable if conflicts
cost more than waiting. The median latency of a call goes, for
`claude-haiku-5-5`, from about 2.5 s (`legacy`) to about 3.9 s (`balanced`). The
bench's prices are assumptions and are not reproduced here.

- **`vague`**: a gambling prediction is worse than none, because it makes the task
  look isolated. When the LLM announces a `broad` scope, an overall confidence
  below `minConfidence`, an empty prediction, more than `maxFiles` files (off by
  default) or, with `verbs: true`, a sweeping verb (refactor, rename, migrate,
  everywhere…), the prediction becomes the **`**` sentinel** (`WHOLE_REPO`): the
  task waits for the active agents — the cautious serialization that is also the
  fallback when the budget is exhausted or the tree truncated. A prediction
  reduced to bookkeeping files is treated the same way (`only-shared-files`).
- **`sharedFiles`**: almost every task touches the changelog, the README, the docs
  or a manifest; leaving them in the prediction would wrongly serialize nearly all
  agents over trivial conflicts the Merger resolves. In `exclude` mode (default),
  these files (`patterns`, case-insensitive globs, 200 at most) are removed from
  collision detection — in the Router as in the runtime net
  ([`overlap`](#overlap--the-runtime-overlap-net)) — but kept in `details.shared`.
  Setting `mode: 'exclude'` explicitly is listed by `doctor`: two agents really
  editing those files are no longer signalled. `'keep'` restores the historical
  behaviour.
- **`details`**: `predictFilesDetailed().details`, exposed in an agent's `routing`
  field (`--json`, Control Protocol), gives each file's confidence, source (`llm`,
  `expansion`, `policy`) and reason, the `shared` list, the `expansion` (reason:
  `test`, `tested-code`, `importer`, `importee`, `sibling`, `contract`,
  `co-change`), the `tree` (mode, files shown) and, when the task was serialized,
  `serialized` (`kind`: `vague`, `budget` or `tree-truncated`, with its reasons).
  An allow-list of fields, bounded: never the raw LLM output, nor the map
  excerpts.
- **`maxScanFiles`**: above it, file contents are not read (no map, symbols or
  import graph); lexical retrieval stays available on paths alone. A file matching
  `secretPatterns` is never read.
- **Tree truncation** (`tree.maxFiles`): declared (`router:tree-truncated` event,
  log, prompt), never silent; `onTreeTruncated` chooses between serializing and
  predicting on the partial view.

**A failed clone does not hold up cautious serialization.** An autonomous clone
whose session ended in failure (anything but `COMPLETED` or `CANCELLED`), with no
commit to merge, waits for a human: it no longer works. Letting it hold back a task
the Router could not locate (the `**` sentinel) would block that task until the
wait timeout for nothing. The `sessionFailure` marker written to the registry by
the end of the cycle (status, instant, commits, session start) therefore lets the
sentinel **not wait for it** — never silently: `task:serialization-relaxed` event,
`SERIALIZATION_RELAXED` warning in the result and `relaxedBlockers` list
(`{agent, reason: 'SESSION_FAILED', status}`). The proof is fail closed: a live
session, a more recent session, a commit or a supervised agent make it
inoperative, and a collision on a specific file on both sides stays blocking in
every case.

## `overlap` — the runtime overlap net

The Router predicts; `overlap` **observes**. In `striart watch` (at start-up, on
every agent-branch commit and at the silent-fetch cadence, `fetchIntervalMs`;
queued on the `watch` chain) and in the state view (`striart status`, Control
Protocol state: `overlaps` field), Striart reads from the clones' git history the
files each agent has **really** modified since its base (`git diff` between
commits, never the index or the worktree) and signals:

- two agents that both touched a file the Router had not predicted on both sides
  (`overlap:observed` event, `kind: 'agents'`);
- an agent and the target branch, which advanced on files it also touches
  (`kind: 'target'`).

The only automatic gesture: an **early rebase** of the agent concerned through the
existing primitive (`overlap:catch-up`), refused on a live session
(`SKIPPED_SESSION`), cancelled on conflict, with no effect under
`watch --no-merge`. Never a merge. Bounded, reported cost (`cost`: git calls, cache
hits).

```js
overlap: {
  enabled: true,            // false = relaxation (shown by doctor): the Router alone judges
  autoSync: true,           // early rebase of an agent whose target moved (autoRebase must stay true)
  maxGitCalls: 64,          // 4 to 1024 git calls per cycle; the rest is deferred and declared (`deferred`)
  maxFilesPerAgent: 5000,   // 10 to 100,000 files kept per agent (above: `truncated`)
  maxFilesPerOverlap: 50,   // 1 to 500 files listed per overlap (the total stays in `fileCount`)
}
```

Declared limits: an agent's **uncommitted** changes are not seen (reading them
would require walking the worktree); a file the agent already merged then touched
again may produce an "agent ↔ target" signal with no real conflict (the early
rebase clears it). An unknown key is refused.

## `idle` — the GC of idle agents and sessions

Detection of forgotten agents and, optionally, closing **their session** (never
their clone): see [`striart gc`](commands.md#striart-gc-agent---close---dry-run)
for the signals, the guards and the closing paths. A partial object merged into
the defaults; an unknown key is refused (a typo on `closeAfterMS` does not slip by
silently).

```js
idle: {
  enabled: true,              // false = relaxation: nothing is detected any more (shown by doctor)
  action: 'report',           // 'report' (detects) | 'warn' (+ warns) | 'close' (+ closes after the grace)
  warnAfterMs: 1800000,       // 60,000 to 30 d — inactivity (all signals) that makes an agent "idle"
  closeAfterMs: 7200000,      // 120,000 ms to 90 d, >= warnAfterMs — minimum inactivity to close
  graceMs: 300000,            // 10,000 ms to 1 d — delay between the warning and the closing
  sweepIntervalMs: 300000,    // 15,000 ms to 1 h — period of the `striart watch` sweep
  maxClosuresPerSweep: 4,     // 1 to 64 closures per sweep
  closePty: false,            // true = relaxation: close a terminal whose output is not observed
  excludeAgents: [],          // 128 at most: exact names or a "name*" prefix — never touched
  excludeProfiles: [],        // 128 at most: profiles (agentProfiles) whose agents are never touched
}
```

- **`action` is a policy, the authorization is the user's decision.** Even with
  `action: 'close'`, nothing is closed until this repository is listed in
  `idle.closeRoots` of the
  [user configuration](#user-configuration-outside-the-repository): a hostile
  repository must not be able, through a committed file, to get processes
  terminated on the machine of whoever opens it. Without authorization (or if the
  user configuration is unreadable), `close` degrades to a warning and the report
  says so (`closeAuthorized: false`); `striart doctor` shows it.
- **Never before the warning or the grace**: a closure requires a warning at least
  `graceMs` old placed *since the last activity*, an inactivity of at least
  `closeAfterMs` and no guard. Any activity resets the counter.
- **`closePty`**: the native pty host publishes the time of its last output in
  `host.output` (at most one write per second, bound to its PID). An older host, or
  a program still silent, does not publish it: the terminal's output is then
  *unobservable* and, by default, the terminal is not closed. The native binary's
  source publishes this file; a binary built or signed before that change does not
  and must be rebuilt then re-signed. `closePty: true` accepts judging "idle" on
  the other signals alone. It is an explicit relaxation.
- **Exclusions**: `excludeAgents` accepts `agent-a` or `ci-*`; a bare `*` is refused
  (excluding everything would amount to disabling — that is `enabled: false`).
## Agent profiles (`agentProfiles`)

How to launch each tool WITHOUT human interaction (autonomous mode). By
default the table holds the **20 ready presets** of the catalog
(`striart profiles --catalog`), each configured so the tool can succeed
(edit, commit per the commit contract) and neutralizing the agent
configuration the repository ships when the tool allows it: `claude`,
`claude-subscription`, `codex`, `gemini` (ACP), `copilot`, `copilot-acp`,
`cursor`, `opencode`, `opencode-acp`, `goose`, `goose-acp`, `amp`, `kilo`,
`kilo-acp`, `qwen`, `qwen-acp`, `cline`, `cline-acp`, `aider` and `ollama`.
Declaring a profile **adds** a vendor without erasing the original ones;
`{ preset: '<id>', … }` derives a profile from a preset (including an
**experimental** one: Gemini over argv, Junie, Junie ACP, Continue, Warp Oz —
which never enter the defaults and show as a relaxation in `doctor`).
`{{prompt}}` is substituted as an **argv element** — never a shell, so no
injection is possible from the prompt text.

```js
agentProfiles: {
  // Derived preset: the fields given win over the preset's.
  claude: { preset: 'claude-code', commitPolicy: 'human' },
  // Hand-written profile (argv): {{prompt}} MANDATORY in args.
  mytool: { command: 'mytool', args: ['--yes', '--message', '{{prompt}}'] },
  // ACP profile: {{prompt}} FORBIDDEN (the prompt goes through the protocol).
  'claude-acp': { command: 'claude-agent-acp', args: [], acp: true },
}
```

Profile fields (all validated; an unknown or invalid field is refused by
name, `PROFILE_INVALID`):

| Field | Role |
|---|---|
| `command`, `args` | The tool and its argv. `{{prompt}}` mandatory in argv, forbidden in ACP. Optional slots: `{{striartInstructions}}` (the instructions text), `{{striartInstructionsFile}}` (path of the instructions file, outside the clone), `{{striartTestCommand}}` (the Test Gate command). |
| `env` | Profile-specific variables merged over the environment (one key per tool). From a `.mjs`, `env: { KEY: process.env.SOURCE }` — never a plain-text secret. |
| `timeout` | Max session time (ms, 1000 to 2147483647). Precedence: `--timeout` > `profile.timeout` > `autonomousTimeoutMs`. |
| `preset`, `experimental` | Preset the profile derives from; "not verified in official documentation" flag. |
| `writeMode` | `workspace` \| `read-only` \| `unrestricted`: what the invocation lets the tool write (declarative, displayed). |
| `commitPolicy`, `commitAuthor`, `commitMessage` | **Per-profile** commit contract (see below). `commitAuthor`: `{ name?, email? }`; default `<key> (Striart agent) <<key>.agent@striart.invalid>`. |
| `structuredOutput` | `none` \| `claude-stream-json` \| `codex-jsonl` \| `gemini-stream-json` \| `ndjson`: the tool's structured output is readably transcribed into the session log and feeds the token ledger. Meaningless in ACP. |
| `instructions` | `{ channel, template, append, flag, encoding }`: instructions delivery channel (`auto`, `acp-prompt`, `system-prompt-file`, `prompt`, `none`) and per-profile template. |
| `settingsFile` | `{ flag, json, claudeMdExcludes? }`: session settings file written by Striart **outside the clone** (`.striart/logs/`) and passed to the tool through `flag` (≤ 64 KiB). |
| `acp` | ACP transport: `true` or an object (see below). |

Without `env`, the session inherits the whole process environment — see
[SECURITY.md](../../SECURITY.md). `striart profiles` lists the configured
profiles (`env` names, never values), `--catalog` the presets, `--detect` the
installed tools.

### `agentProfiles.<name>.acp` — the ACP transport

```js
acp: {
  permissions: 'allow',       // 'allow' | 'reject' | 'ask' — default 'allow' (see below)
  askTimeoutMs: 120000,       // 1,000 to 86,400,000 — human arbitration delay ('ask'), fail closed beyond
  auth: { methodId: '…' },    // EXPLICIT decision to authenticate; never automatic (relaxation)
  persistentHost: true,       // session carried by a detached host (Phase E, IDE proxy)
  bus: true,                  // the host accepts `@agent` human messages
  terminal: true,             // or { timeoutMs: 600000, outputByteLimit: 1000000, maxTerminals: 8 }; false = disabled
  fsReadMaxBytes: 4194304,    // 1,024 to 268,435,456 — ceiling of a file served to fs/read_text_file (4 MiB)
  mcp: 'striart',             // 'striart' (read-only MCP bound to the clone) | 'none'
  elicitation: { form: true, url: false },   // only with permissions: 'ask'
}
```

`allow` is the trust level of the historical headless profiles: isolation
comes from the clone and authority from the Test Gate, not from the
permission policy. `ask` is the **semi-autonomous** mode: every permission,
and every structured question of the agent (elicitation), is arbitrated by
the human — dashboard, `striart api` or editor — and refused at the deadline.
Elicitation requested without `ask` is refused at load
(`ACP_ELICITATION_NEEDS_ASK`): a capability advertised with no human to
answer would be dead. Relaxations (listed by `doctor`): `auth.methodId`,
`elicitation.url`, and a `terminal` more permissive than the values above.
Striart's ACP client handles `auth_required` (it stops on
`ACP_AUTH_REQUIRED` — it never authenticates on its own, unless
`auth.methodId` is set), elicitation, clone-bound terminals and clone-bound
files (symlinks included).

## `commitPolicy`, `commitMessage` — who commits

`commitPolicy` decides who commits the work left by an autonomous session
that exited `COMPLETED`, globally and per profile:

| Value | Effect |
|---|---|
| `agent` (default) | The agent alone; it committed nothing → clone kept (`NO_COMMIT`). |
| `agent-then-striart` | The agent; if it committed nothing, Striart commits what it left. |
| `striart` | Striart always commits the uncommitted rest. |
| `human` | Nobody commits **or merges**: clone kept for human review. If the agent committed anyway, the cycle returns `KEPT` / `HUMAN_REVIEW_REQUIRED` and **never** merges — in every mode (single cycle, orchestrated modes, ACP proxy); exit 3 (breaking change announced in the CHANGELOG). |

The Striart commit never carries an excluded file (`secretPatterns`, files
injected by Striart, even tracked or already staged — rechecked on the
produced commit), has the agent profile as **author** and the user's git
identity read from the main repository as **committer**
(`COMMITTER_IDENTITY_MISSING` otherwise), and never applies to a clone in an
ambiguous state. `commitMessage` is the message template
(`striart({{agent}}): {{task}}` by default; placeholders `{{agent}}`,
`{{profile}}`, `{{task}}`, `{{taskId}}`, `{{branch}}`, 4,000 characters at
most, non-empty subject); `Striart-*` *trailers* are always added and the
subject is never mistaken for a Striart merge. The `codex` preset defaults
to `striart`: Codex's sandbox makes `.git` read-only, the agent cannot
commit.

## `agentInstructions` — the rules handed to agents

An agent launched in a clone knows nothing about Striart. Striart therefore
hands it its rules (isolated clone, only *committed* work is integrated, Test
Gate, no push, no change to agent files, commit conventions, MCP rules,
protected paths, the collaboration channel when the agent is in a group)
through the channel suited to the tool. Key-wise merge with these defaults:

```js
agentInstructions: {
  enabled: true,              // false = relaxation: agents receive no rule
  template: null,             // full replacement template (≤ 32 KiB, known placeholders only)
  append: null,               // text appended to the end of the template
  commitConvention: 'Conventional Commits — "<type>(<scope>): <summary>" …',
  agentsMd: 'override',       // 'override' | 'non-file': what to do when AGENTS.md exists
  attendedFiles: {},          // per-tool instruction files, in supervised mode (paths relative to the clone)
  genericFiles: ['AGENTS.md'],// files for an unrecognized tool
  neutralizeParentInstructions: true,  // excludes the main repo's CLAUDE.md files the clone inherits
}
```

Channels: a block at the head of the ACP prompt; a system-instructions file
outside the clone (`--append-system-prompt-file`, `--read`…); a prompt
envelope; or, in supervised mode, an **untracked file** in the clone,
excluded by the *clone's* `.git/info/exclude`. When a tracked `AGENTS.md`
exists, `agentsMd: 'override'` drops a composite `AGENTS.override.md` (for
tools that read it, like Codex); `'non-file'` touches nothing next to
`AGENTS.md` and prefers a file-less channel. Template placeholders:
`{{agent}}`, `{{mode}}`, `{{tool}}`, `{{profile}}`, `{{branch}}`,
`{{targetBranch}}`, `{{testCommand}}`, `{{commitRules}}`,
`{{commitConvention}}`, `{{mcpRules}}`, `{{protectedPaths}}`, `{{extra}}`.
`tokens.instructions.mode: 'compact'` divides the default template's token
estimated cost by about 3.6 (1,400 → 385 estimated tokens with the
default template, `npm run bench:tokens` run on 2026-10-26). The instructions are *advisory*: the safeguards (Test
Gate, protected paths, MCP guard) decide, and an injection failure is a
warning, not a refusal.

## `protectedAgentPaths` — the paths an agent never changes

An agent that modifies a file that **instructs or configures** coding agents
— `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.claude`, `.codex/`, `.cursor/`,
`.mcp.json`, `.vscode/settings.json` (auto-approval, cf. CVE-2025-53773),
`.github/hooks/`, `opencode.json`… 81 patterns verified against the
tools' documentation — or **Striart's config** (`striart.config.*`,
`.striartrc*`, `.striart/`, the `striart` key of `package.json` included) has
its **merge refused**: a `PROTECTED_PATHS_CHANGED` ticket, before any LLM
merge and before the Test Gate. These files are re-read by *later* sessions
with the trust given to the repository: letting them through would turn a
one-off prompt injection into a persistent compromise, or disarm the Test
Gate (an agent rewriting `testCommand`). The refusal triggers on an
*effective* change (the content brought differs from the target branch's).

```js
protectedAgentPaths: {
  extend: [],               // added patterns (root-anchored globs, / separator)
  allow: [],                // patterns REMOVED from the defaults — a relaxation logged at every merge
  matchCase: 'insensitive', // 'insensitive' (default) | 'platform' (case-sensitive outside Windows/macOS: relaxation)
}
```

Patterns: `*` (anything but `/`), `?`, `**` as a whole segment; no `[…]`
classes, braces nor negation. `x/**` covers `x` itself (even replaced by a
file or a submodule) and all its content. An absolute pattern, or one with
`..` or `\`, is refused at load.

The defaults also cover **auto-execution** points: `.vscode/tasks.json`
(`folderOpen` task), `.devcontainer/` and `.devcontainer.json`, `.husky/`,
`.githooks/`, `.envrc`, `.pre-commit-config.yaml`, `lefthook.*`. Comparison is
made on a **normalized** path (NFKC, lower case: `AGENTſ.md` is `AGENTS.md`)
and any segment shaped like a Windows short name (`CLAUDE~1.MD`) is treated as
protected. `package.json` cannot be protected whole: only its `striart` key is
— an accepted partial perimeter (an agent may change your npm scripts; the Test
Gate stays the authority).

## `acpRegistry` — importing ACP agents

```js
acpRegistry: {
  url: 'https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json',  // https required
  allowBinaryDownload: false,   // true: `--import-acp` may DOWNLOAD a binary (relaxation)
  allowEnv: [],                 // names of environment variables a registry agent may set
}
```

**Metadata only** by default. Downloading requires a pinned version, a
published and verified sha256 checksum, an extraction with no symlink nor
escaping path; it is logged and shown by `doctor`.

A registry agent may ask for environment variables (`env`). They are
**refused** (`ACP_IMPORT_ENV_FORBIDDEN`) unless their name is in
`allowEnv` — and **never** for an interpreter or loader variable
(`NODE_OPTIONS`, `PATH`, `LD_*`…), even if listed: a registry does not put
code into a session's environment.

## `acpAgent` — the ACP proxy (`striart acp`)

Settings of `striart acp`; a partial object, its keys replace those of the
defaults. An unknown key is refused (`CONFIG_INVALID`, field
`acpAgent.<key>`).

```js
acpAgent: {
  defaultProfile: null,          // upstream profile offered by default (null: the first ACP profile alphabetically)
  profiles: null,                // allow-list of profiles offered to the IDE (null: every `acp: true` profile)
  permissions: 'ask',            // 'ask' | 'reject' | 'allow' | 'profile' — a session's default policy
  permissionChoices: ['ask', 'reject'],  // policies the human can pick from the IDE
  askTimeoutMs: null,            // 1,000 to 86,400,000; null: the profile's
  merge: 'auto',                 // 'auto' (merge under Test Gate at the end) | 'manual' (clone kept)
  mergeChoice: true,             // the human can toggle auto/manual from the IDE
  onDisconnect: 'keep',          // IDE closed without an explicit end: 'keep' (clone kept) | 'finish' (relaxation)
  agentName: null,               // FIXED clone name (null: derived from the first prompt)
  reuse: false,                  // rehabilitates an archive of the same name (requires agentName)
  collisionPolicy: 'fail',       // Router collision on the first prompt: 'fail' | 'wait'
  collisionWaitMs: 600000,       // 1,000 to 86,400,000
  collisionPollMs: 2000,         // 100 to 600,000
  sessionTimeoutMs: 14400000,    // 60,000 to 7 days — max session time (clone kept beyond)
  relayThoughts: true,           // relays the agent's reasoning (agent_thought_chunk)
}
```

Relaxations: `permissions: 'allow'` (or `'allow'` in `permissionChoices`),
`'profile'` (the upstream profile's policy applies, `allow` by default),
`onDisconnect: 'finish'`. The default policy must appear in
`permissionChoices`; `reuse: true` requires `agentName`.

## `terminal` — the `--open` launcher

```js
terminal: {
  launcher: 'auto',      // 'auto' | 'wt' | 'warp' | 'terminal-app' | 'iterm' | 'gnome-terminal'
                         // | 'konsole' | 'kitty' | 'wezterm' | 'alacritty' | 'custom'
  detectWarp: true,      // in 'auto': TERM_PROGRAM=WarpTerminal → Warp tab
  holdShell: 'bash',     // shell that keeps the tab open (Linux, kitty…) — [A-Za-z0-9._/-], 200 chars max
  warp: {
    channel: 'auto',     // 'auto' (from TERM_PROGRAM_VERSION) | 'stable' | 'preview'
    shell: null,         // 'pwsh' | 'bash' | 'zsh' | 'fish' (null: the OS default)
    newWindow: false,    // warp://tab_config/<name>?new_window=true
    tabConfigDir: null,  // Warp's tab_configs directory (absolute path; null: the documented per-OS location)
  },
  custom: null,          // { command, args } — argv, NEVER a shell
}
```

`auto` keeps the historical behavior (Windows Terminal if `WT_SESSION`,
otherwise a PowerShell console; Terminal.app; gnome-terminal) and recognizes
a Warp session. The `custom` launcher receives its argv with placeholders
substituted *inside the element*, in a single pass: `{{argv}}` (whole element
only — the attach argv as several elements), `{{posixCommand}}` /
`{{powershellCommand}}` (the same command quoted for a POSIX / PowerShell
shell, to pass to a `-c`/`-Command`), `{{cwd}}`, `{{title}}`, `{{agent}}`.
One of the first three is mandatory: without it the tab would open without
ever attaching to the agent. Each launcher is explicitly refused outside its
platform (`TERMINAL_LAUNCHER_UNSUPPORTED`). **Warp** runs no command through
its URI scheme: Striart writes a *Tab Config*
(`striart-<agent>-<fingerprint>.toml`, mode 0600, single pane in the clone,
attach command quoted for the chosen shell) and opens it through
`warp://tab_config/<name>`. That file is removed by `striart stop` and
`striart clean` (`removeWarpTabConfig`, through the release of the agent's
artifacts); a failed removal is reported (`AGENT_ARTIFACT_FAILED` warning),
the file is then removed by hand.

## `pty` — the native terminal host

```js
pty: {
  replayBytes: 65536,        // recent output replayed to an attaching client (1 KiB to 16 MiB)
  clientQueueBytes: 4194304, // a client's queue beyond which it is evicted (32 KiB to 256 MiB, and at least ⌈replayBytes×4/3⌉ + 64 + two output frames: the replay is sent as one base64 frame)
  killGraceMs: 1000,         // time left to the shell and its descendants on close (0 to 60,000)
  shell: 'auto',             // 'auto' | bare name (absolute PATH only) | absolute path
  shellArgs: [],             // ≤ 64 arguments, each ≤ 4096 bytes, no newline nor NUL
}
```

`shell: 'auto'` = PowerShell on Windows, `$SHELL` or bash elsewhere. A bare
name is resolved in the **absolute** `PATH` entries only (never the current
directory), a path must be absolute; nothing is passed to a shell (argv).
Precedence: the agent's explicit command > `pty.shell` > `auto`; no fallback
on failure (`PTY_SHELL_INVALID`). Choosing an executable in a repository's
config is a relaxation (config-as-code): `striart doctor` shows it. On
Windows, PowerShell 5.1 loads your profiles at every start (slow, and refused
by a strict execution policy): set `shellArgs: ['-NoLogo', '-NoProfile']`, or
`shell: 'pwsh'` (PowerShell 7 — Striart does not prefer it automatically: the
gain is not demonstrated).

## `lock` — the main lock

```js
lock: { breakFrozenHolderAfterMs: null }   // null (safe default) | integer ≥ 60,000
```

A **live** main-lock holder whose heartbeat is frozen (frozen process:
debugger, `SIGSTOP`, synchronous loop) is **never** broken by default:
breaking it would leave two processes in the critical section when it thaws.
The wait ends in `LOCK_TIMEOUT` (`HOLDER_FROZEN`) with the PID to stop. An
integer ≥ 60,000 ms allows breaking beyond that delay without a heartbeat
(after an active 15 s observation, which a machine sleep does not distort): a
relaxed protection, **logged at every break** and shown by `striart doctor`.

## `mcp` — the MCP server

```js
mcp: {
  scope: 'agent',            // 'agent' (default) | 'orchestrator' (relaxation)
  apps: true,                // MCP Apps view (read-only) of the 3-way ticket
  tasks: true,               // Tasks extension for long operations (merge, apply, promote)
  taskTtlMs: 3600000,        // 60,000 to 7 days — retention of a finished task
  taskPollIntervalMs: 2000,  // 100 to 60,000 — cadence suggested to the client
  maxLineBytes: 1048576,     // 4,096 to 64 MiB — bound of a JSON-RPC request
  maxConcurrentRequests: 4,  // 1 to 64 — tools/reads executed in parallel
  maxQueuedRequests: 64,     // 0 to 4096 — waiting ("overloaded" refusal beyond)
}
```

`scope: 'agent'`: a server started from a clone (or `--agent`) acts only on
**its** agent; outside a clone it is read-only. `'orchestrator'` grants,
outside a clone, `run`/`merge`/resolution on the whole repository — never
closing a ticket without the Test Gate nor arbitrating a permission, at any
level. See [MCP server](mcp.md).

## `orchestration` and `collab` — orchestration modes, collaboration

Partial objects, deep-merged with these defaults (unknown key refused). They
tune `striart plan` (version 2) and `striart orchestrate`.

```js
orchestration: {
  concurrency: 2,            // simultaneous tasks of a `parallel` plan (≤ maxConcurrency)
  maxConcurrency: 8,         // hard cap (1 to 64)
  onFailure: 'stop',         // 'stop' (nothing else starts) | 'skip-dependents'
  collisionPolicy: 'wait',   // Router collision: 'wait' (bounded wait) | 'fail'
  pollIntervalMs: 2000,      // 100 to 60,000
  waitTimeoutMs: 86400000,   // 1,000 to 30 d — wait for a dependency or a collision (fail closed)
  keepRuns: 50,              // 1 to 10,000 — finished plan/group states kept
  review: { maxRounds: 3,            // 1 to 10 correction rounds
            verdictRetries: 1,       // 0 to 3 new requests for a missing/invalid verdict
            quorum: 'all',           // 'all' | 'any' | 'majority'
            reviewerWrites: 'fail',  // 'fail' | 'discard' (relaxation: reviewer writes reset)
            humanTimeoutMs: 86400000 // 60,000 to 30 d — a human reviewer's delay (fail closed)
          },
  race: { pick: 'first-green',       // 'first-green' | 'smallest-diff' | 'judge'
          losers: 'keep',            // 'keep' | 'archive' | 'clean' (relaxation: deleted with their work)
          maxCandidates: 5,          // 2 to 10
          judgeFallback: 'fail' },   // 'fail' | 'first-green' if the judge fails
  team: { cadence: 'turns',          // 'turns' (one writer at a time) | 'parallel' (static partition)
          rounds: 1, maxRounds: 10,  // 1 to 10
          onScopeViolation: 'fail' },// 'fail' | 'warn'
  pipeline: { handoff: 'merge' },    // 'merge' (each step merged) | 'clone' (a single merge)
},
collab: {
  enabled: true,             // false: no more free messages (the modes remain)
  maxMessages: 200,          // 1 to 10,000 per group
  maxBodyBytes: 8192,        // 256 to 262,144 per message
  maxMessagesPerSender: 50,  // 1 to 10,000
  inboxFile: true,           // `.striart-inbox.md` delivered into the clone
  outboxFile: true,          // `.striart-outbox.json` read at the end of the turn
  maxOutboxBytes: 65536,     // 1,024 to 4 MiB
  briefingMaxChars: 12000,   // 1,000 to 24,000 — relay/turn briefing
  logMarkers: true,
},
```

Safe defaults: a failure stops everything that has not started, the losers of
a race are kept, a reviewer that writes fails the review. The relaxations
(`race.losers: 'clean'`, `review.reviewerWrites: 'discard'`) are shown by
`doctor`. **Dynamic** partitioning (`team.cadence: 'dynamic'`) does not
exist: it is refused at validation (`CADENCE_UNAVAILABLE`) until write
arbitration is wired. Mode details:
[Execution modes](execution-modes.md#the-orchestration-modes).

## Dashboard and Control Protocol

`dashboardPort` (3456) is the default port. The dashboard only listens on
`127.0.0.1` and requires a session obtained through a **one-time link**
(`dashboardLinkTtlMs`, 10 s to 24 h); the session cookie lives
`dashboardSessionTtlMs` (1 min to 30 days). `controlSseMaxBufferedBytes`
(64 KiB to 256 MiB) is the queued volume beyond which a too-slow SSE client
is disconnected (it reconnects and receives the full state);
`controlStateMaxDelayMs` (300 ms to 60 s) bounds the delay between a change
and its notification.

`dashboardHostname` (`'instance'` by default): the dashboard is served at
`http://<random-id>.localhost:<port>`, a name drawn at each start and
resolved to loopback by browsers. Why: a cookie is not isolated by port (RFC
6265 §8.5) — under `localhost` the browser would send the session cookie to
any `localhost:*` server, for example an agent's dev server that could replay
it. Under an instance-specific name it is never sent elsewhere, and the
"bare" `localhost` address is **no longer served** (403 non-local `Host`,
unless in `dashboardAllowedHosts`). The printed sign-in link carries this
name. `'localhost'` is a relaxation (config-as-code): logged at every start
and shown by `doctor`; reserve it for a browser that cannot resolve
`*.localhost`.

`dashboardAllowedHosts` (empty by default) accepts **additional** `Host`
headers: behind a web tunnel (Codespaces `*.app.github.dev`, a corporate
reverse proxy), the browser sends the public name. Strict patterns: an exact
name (`striart.example.com`), a single-level leading wildcard under a suffix
of at least two labels (`*.app.github.dev`), an exact private or loopback
IPv4, an optional port; refused: `*`, `*.com`, a wildcard elsewhere, several
wildcards, a public IP, IPv6, a scheme, a path, credentials. This setting
**only relaxes** the `Host` check: token, `SameSite=Strict` cookie,
`Sec-Fetch-Site`, `Origin` and anti-CSRF remain required. It is logged at
every dashboard start and shown by `doctor`.

## Delivery to `origin`: `autoPush`, `delivery`, timeouts

`autoPush: true` delivers every green merge (and every promotion) to the
`origin` remote; `delivery` chooses **where**:

- `'push'` (default): the tested SHA goes to `targetBranch` (to `mainBranch`
  for a promotion);
- `'branch'`: it goes to a branch **awaiting approval** —
  `striart/<agent>/<task>` (`<task>`: the task identifier if it uses a safe
  character set, otherwise a UTC timestamp), `striart/promote/<date>-<sha8>`
  for a promotion. The remote target branch **never** advances because of
  Striart: the forge stays the approval authority (PR/MR created elsewhere).
  `delivery: 'branch'` without `autoPush: true` is refused at load time
  (`CONFIG_INVALID`, sub-code `DELIVERY_REQUIRES_AUTOPUSH`): it would suggest a
  delivery that does not happen.

In both modes the delivery is a **deferred** effect, run **after the main lock
is released**, and covers the **exact SHA** that passed the Test Gate — never
`HEAD`. It is **never forced** and cannot open an interactive prompt
(`GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`, no inherited `GIT_*`
variable). A failure does not undo the local merge: it is reported in
`result.delivery` (typed report: mode, branch, SHA, `pushed`, `code`, hint) and
in `pushError`, prefixed with the code (`[PUSH_TIMEOUT] …`), with a
`delivery:failed` event (webhook); in `branch` mode the `delivery:branch` event
announces the delivered branch. Remote URL tokens are redacted
(`https://***@forge/`). Reported codes: `PUSH_TIMEOUT`,
`PUSH_NON_FAST_FORWARD`, `PUSH_REJECTED`, `PUSH_FAILED`, `PUSH_SUPERSEDED`,
`DELIVERY_REF_INVALID` — see [Troubleshooting](troubleshooting.md#error-codes).

- `pushTimeoutMs` (120,000, 1,000 to 2,147,483,647): hard push timeout. Beyond
  it the **process tree** is killed (`pre-push` hook, authentication or network
  blocked): `PUSH_TIMEOUT`.
- `commitTimeoutMs` (300,000, 1,000 to 2,147,483,647): same guard for the
  **merge commit**, which runs the target's hooks (`pre-commit`,
  `pre-merge-commit`, `prepare-commit-msg`, `commit-msg`) and signing. A hook is
  **never bypassed** (no `--no-verify`): a rejection or a timeout cancels the
  merge and opens a `COMMIT_HOOK_REJECTED` ticket (hook output bounded to
  16 KiB, the tail kept). This timeout also bounds the `revert` commit of a
  published `rollback`.

Deliveries are serialized per repository **within one process**; between two
processes (a `watch` and a command), a push refused because the other one has
just published that same SHA is recognised as already delivered
(`alreadyDelivered`). **Accepted residual window**: a `rollback` run by
*another* process during an in-flight push is not prevented; when the
divergence is detected it is reported (`PUSH_SUPERSEDED` if the SHA is no
longer in the local branch, `PUSH_NON_FAST_FORWARD` if the remote moved),
never silently. `striart doctor` does not show `delivery` or these timeouts.

## Test Gate: process container

The Test Gate (`testCommand`, `promoteTestCommand`) runs by default in the
**native process container** (`striart-native job run`: Job Object on
Windows, group + subreaper on Linux).

- `testTimeoutMs` (600,000, 1,000 to 2,147,483,647): beyond it the tree is killed and the
  gate is red.
- `gateOrphanGraceMs` (2,000, 0 to 600,000): when the command exits, its
  descendants have this delay to finish by themselves. A descendant still
  alive is an **orphan**: it is killed and the gate is **red**
  (`GATE_ORPHAN_PROCESS`) **even if the command returned 0** — a test that
  leaves a process behind leaks, it is not a success.
- `gateMaxOutputBytes` (100 MiB, 1 KiB to 1 GiB): cap of the kept log; the
  **tail** of the output is kept, the rest discarded (the result carries
  `truncated`).
- `gateContainer`: `'native'` (default) or `'process'`. Without a healthy
  native binary the gate is **not run** and returns red
  `GATE_NATIVE_UNAVAILABLE` (fail closed). `'process'` is the explicit
  relaxation: classic execution, tree killed at the timeout only, **no
  orphan detection**.

The gate is also red if the container cleanup is incomplete
(`JOB_TERMINATE_INCOMPLETE`).

### `gateEnv` — the Test Gate environment

`testCommand` runs tests that **the agent may have written or modified**:
handing them the whole orchestrator environment (LLM API keys, webhook URLs,
tokens) would offer it to untrusted code. The gate therefore receives an
**allow-list** (paths, temp directories, locale, proxy and certificate
authorities for `npm install`, `NODE_*`, `npm_config_*`, `XDG_*`, `STRIART_*`,
toolchain locations…), **without** anything whose name looks like a secret, and
**always without** API keys (`*_API_KEY`), webhook URLs, the variables the config
names to carry them (`llm.apiKeyEnv`, `llmRoles.*.apiKeyEnv`,
`notifiers[].urlEnv`) and `STRIART_SESSION`.

- `gateEnv: null` (default): that allow-list only.
- `gateEnv: ['MY_APP_*', 'DATABASE_URL']`: the repository **requests** extra
  variables (up to 64: a name, `PREFIX_*` or `*_SUFFIX`; a request aimed at an
  API key or a webhook is refused at load time). They pass only if the **user
  configuration** allows them (`gate.envAllow`, below): the repository cannot
  widen beyond what the user permits. An unauthorized request is dropped — never
  silently accepted: the gate log opens with a line naming the dropped
  variables ("gateEnv : variables demandées par le dépôt mais non autorisées par
  la config utilisateur (gate.envAllow), non transmises : …" — names only, the
  line itself is in French) and `striart doctor` (line "Test Gate environment") flags it.
- `gateEnv: 'inherit'`: the whole orchestrator environment, API keys included.
  **Explicit relaxation**, logged and shown by `doctor`.

The gate log is also **redacted** before being kept or returned (see
[SECURITY.md](../../SECURITY.md#confidentialité-des-données-locales)): keys
recognised by their shape, and the exact values of the environment's secrets.

## Logs

`logMaxBytes` (10 MiB by default, 64 KiB to 1 GiB) and `logGenerations` (5,
from 1 to 100) tune the size-based rotation of the long logs (`watch.log`,
`dashboard.log`, `watch-ui.log`): beyond it, the log becomes `<name>.log.1`,
then `.log.2`… the oldest generation being deleted. `STRIART_LOG_LEVEL` sets
the verbosity of CLI logs (stderr). Session, Test Gate and ticket logs are
**redacted** before being written (known secret patterns and the exact values
of the environment): see
[SECURITY.md](../../SECURITY.md#confidentialité-des-données-locales).

## Local data: `privateStateDir`

`.striart/` holds source code (the base/ours/theirs versions of tickets), tool
output (session and gate logs), the queue's prompts and the Control Protocol
tokens. `privateStateDir: true` (default) reserves it to the current user:
directories `0700` and files `0600` (POSIX, checked with `stat`), a **protected
ACL** without inheritance, limited to the user's SID, set by `icacls` and
verified in SDDL (Windows). The protection is set by `striart init` (which also
tightens a pre-existing `.striart/`, idempotently) and before any operation
under the main lock — **before** taking it, never under it — once per root and
per process, and only if `.striart/` exists. Agent clones (`agents/`) and clones
being removed (`removing/`) are **never walked**: they are working trees whose git
objects are hardlinks shared with the main repository — changing their ACL would
change the main repository's too.

A tightening that cannot be done (file system without permissions, foreign
owner, failing `icacls`) is a **refusal**: `STATE_UNPROTECTED` (exit 3), never a
silent fallback. `privateStateDir: false` is the **explicit relaxation** for a
file system that carries no permissions (FAT, exFAT, some network shares): one
warning per process, and `striart doctor` shows it (the "Local data
(.striart/)" and "Relaxed protections" lines). An unreadable config never
disables the protection.

## Notifications

Two cumulative mechanisms, best-effort (a failing webhook never blocks
orchestration):

- `webhookUrl` — historical single channel, the type (Slack/Discord) is
  guessed from the URL;
- `notifiers` — multi-channel table with an explicit type (`slack` →
  `{text}`, `discord` → `{content}`, `generic` → `{message}`). The URL comes
  from `url` or `urlEnv` (name of an env variable — preferable: a webhook URL
  is a secret), never both.

## Enterprise network (`network`)

**Every outgoing Striart call goes through a single entry point**
(`src/net.ts`, enforced by a test that fails if another module calls `fetch()`
or `http(s).request()`): LLM calls (Ollama, OpenAI-compatible, Anthropic,
Azure), notification webhooks, the Ollama probe of `init`/`doctor`, the ACP
registry and the download of its archives. For every **non-local** call the
layer enforces, in this order: a valid `http(s)` URL (`NET_URL_INVALID`);
offline mode (`NET_OFFLINE`); the host allow-list (`NET_HOST_NOT_ALLOWED`);
**HTTPS required, with or without an API key** (`NET_INSECURE_TRANSPORT`,
reason `PLAIN_HTTP`); TLS verification never switched off
(`NODE_TLS_REJECT_UNAUTHORIZED=0` is refused, reason
`TLS_VERIFICATION_DISABLED`); **no redirect followed** (`NET_REDIRECT_REFUSED`)
— except the **bounded** following (3 hops) of ACP registry archives, where
every hop goes through all these checks again. The loopback (`localhost`,
`127.x`, `[::1]`) is neither proxied nor subject to these rules, and does not
even read the user configuration: a local Ollama never depends on it.

**Network settings are the user's decision, never the repository's**: they live
in the shell and in the [user configuration](#user-configuration-outside-the-repository),
out of reach of a hostile repository (which could otherwise redirect traffic
to its own proxy, add its own certificate authority or reopen an allow-list).
The root `.env` filter refuses each of these variables (`*_PROXY`, `NODE_*`,
`STRIART_OFFLINE`, `STRIART_ALLOWED_HOSTS`, `STRIART_TLS_MIN_VERSION`,
`STRIART_PROXY_AUTH`…).

The `network` block of the user configuration (every key is optional; an
unknown key is refused, `USER_CONFIG_INVALID`):

| Key | Default | Role |
|---|---|---|
| `proxy` | `null` | `http://` or `https://` URL of the corporate proxy, **without credentials** (those go in `STRIART_PROXY_AUTH`). |
| `noProxy` | `null` | Hosts reached without the proxy, comma-separated (`NO_PROXY` semantics: `*`, exact host, `.suffix`). |
| `caFile` | `null` | **Absolute** path of a PEM file (≤ 4 MiB, at least one certificate), **added** to the default authorities. |
| `allowedHosts` | `[]` | Allow-list (128 at most): `example.com` or `*.example.com` (subdomains only, never the apex; no scheme, no port, no bare `*`). Empty = no restriction. |
| `allowInsecureHosts` | `[]` | Hosts reachable over **plain** HTTP (128 at most, same patterns): a logged relaxation (once per host), shown by `doctor`. |
| `offline` | `false` | `true`: every non-local call is refused (`NET_OFFLINE`). |
| `tlsMinVersion` | `null` | `'TLSv1.2'` or `'TLSv1.3'`; `null` = Node's minimum. |

Matching **shell** environment variables:

| Variable | Effect |
|---|---|
| `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` (lowercase accepted) | Corporate proxy, when `network.proxy` is absent (`network.proxy` wins). |
| `STRIART_PROXY_AUTH` | The proxy's `user:password`, applied to the proxy URL if it carries none. Never in config, never passed to agent sessions. |
| `STRIART_OFFLINE` | `1`/`true`/`yes`/`on` (or `0`/`false`/`no`/`off`): offline mode. Any other value is refused (`USER_CONFIG_INVALID`). |
| `STRIART_ALLOWED_HOSTS` | Comma-separated allow-list (same patterns as `allowedHosts`). |
| `STRIART_TLS_MIN_VERSION` | `TLSv1.2` or `TLSv1.3`. |
| `NODE_EXTRA_CA_CERTS`, `NODE_USE_SYSTEM_CA=1` / `--use-system-ca` | Certificate authorities added by Node itself, **at startup** (not read by Striart; `doctor` shows them). |

**The two sources are combined, always on the restrictive side**: offline mode
is on if either asks for it; the allow-list is the **intersection** (a host must
appear in every defined list); for TLS the **strictest** wins.

**The proxy, by Node version.** Node only reads `HTTP(S)_PROXY` from certain
versions on, and Striart refuses to bypass a proxy it cannot apply:

- Node **≥ 24.14 / 25.4**: `http.setGlobalProxyFromEnv`, applied at runtime —
  `network.proxy` and `STRIART_PROXY_AUTH` work;
- Node **≥ 22.21 / 24.5**: start Striart with `NODE_USE_ENV_PROXY=1` (or
  `--use-env-proxy`) — Node then reads `HTTP(S)_PROXY` itself; `network.proxy`
  and `STRIART_PROXY_AUTH` are **not** applicable (put the credentials in the
  `HTTPS_PROXY` URL);
- otherwise (or a scheme other than `http:`/`https:`, SOCKS included): the proxy
  is *configured but inactive*, and every call that should go through it is
  refused (`NET_PROXY_UNSUPPORTED`, reasons `SCHEME`, `NEEDS_STARTUP_FLAG`,
  `USER_CONFIG_NEEDS_RUNTIME_API`, `AUTH_NEEDS_RUNTIME_API`).

**Not supported**: `ALL_PROXY` (not read) and SOCKS proxies.

**Corporate CA and agent sessions.** `network.caFile` is read on first use and
added to Node's authorities; an unreadable file or one without a certificate
gives `NET_CA_INVALID`. A chain that does not end at a known authority gives
`NET_TLS_UNTRUSTED`: the way out is to add the corporate CA, **never** to switch
verification off. For an agent's tool (often a Node program) to trust the same
authority, a session receives `NODE_EXTRA_CA_CERTS=<network.caFile>` — unless the
shell already set another one (a single value is possible: **the shell wins**,
and the fact is logged). The `env` of an agent profile (repository config) comes
after, like any profile variable. `STRIART_PROXY_AUTH` is never passed on;
ordinary proxy variables stay inherited as they are — a `network.proxy` from the
user configuration is **not** converted into `HTTP(S)_PROXY` for sessions (not
decided: the agent tool must get its proxy from the shell).

`striart doctor` (the "Network" line) shows the effective policy: offline and
allow-list, proxy active or inactive and its mechanism, minimum TLS, corporate
CA (certificate count), `NODE_EXTRA_CA_CERTS`, and, as a warning, relaxed
protections (`network.allowInsecureHosts`, `NODE_TLS_REJECT_UNAUTHORIZED=0`).

**Accepted limits**: the layer checks the **host name**, not the resolved IP
address — an allowed host whose DNS is hijacked (DNS rebinding) is not
detected; the `network.caFile` → agent sessions path is not tested against a
real HTTPS proxy (tests cover the policy, the environment proxy and the TLS
chain separately).

## User configuration (outside the repository)

Some settings **widen code execution**; they cannot live in a repository's
config, which a hostile repository would supply. They fit in a **user** JSON
file, plain data (never executed), at:

- `$STRIART_CONFIG_HOME/config.json` if set (absolute path);
- otherwise `%APPDATA%\striart\config.json` (Windows);
- otherwise `${XDG_CONFIG_HOME:-~/.config}/striart/config.json` (Linux,
  macOS).

```json
{
  "hooks":  { "trustedRoots": ["/absolute/path/to/repo"] },
  "env":    { "allow": ["MY_PROVIDER_*", "*_SECRET_ID"] },
  "native": { "trustedKeyIds": ["0123456789ABCDEF"] },
  "network": { "proxy": "http://proxy.example.com:3128", "allowedHosts": ["api.anthropic.com", "*.openai.azure.com"] },
  "gate":   { "envAllow": ["MY_APP_*", "DATABASE_URL"] },
  "idle":   { "closeRoots": ["/absolute/path/to/repo"] }
}
```

`hooks.trustedRoots` (256 roots at most, absolute paths, never the
filesystem root) lists the repositories whose config a hook installed for
the user may load **in full** — an executable `striart.config.mjs`
included; elsewhere, the hook only reads data configs. Any anomaly (invalid
JSON, unknown key, file writable by group or others on POSIX — `chmod 600`)
yields **no trust** (fail closed) and a warning (`USER_CONFIG_INVALID`,
`USER_CONFIG_UNSAFE`). Every use is logged and `doctor` shows the trusted
roots.

- `env.allow` (128 patterns at most): names of variables that a repository's
  root `.env` may add to the environment **on top of** the built-in
  allow-list. Shape: an UPPERCASE name, `PREFIX_*` or `*_SUFFIX`. A pattern
  aimed at a deny-listed variable (`NODE_*`, `LD_*`, `PATH`…) is refused: the
  deny-list is never relaxable.
- `native.trustedKeyIds` (16 at most): signing key identifiers (minisign, 16
  **uppercase** hexadecimal digits; the one of the binary in use is shown by
  `doctor`) accepted **in addition to** the key pinned in the code to verify
  the native binary — for an organization that re-signs its own archives.

- `network`: the corporate network policy, detailed in
  [Enterprise network](#enterprise-network-network) (proxy, `noProxy`,
  `caFile`, `allowedHosts`, `allowInsecureHosts`, `offline`, `tlsMinVersion`).
- `gate.envAllow` (128 patterns at most): the **ceiling** of the variables the
  repository's `gateEnv` key may request for the Test Gate, on top of the
  built-in allow-list. Shape: a name, `PREFIX_*` or `*_SUFFIX`; a pattern aimed
  at an API key or a webhook is refused (those variables are always removed from
  the gate). A repository request this ceiling does not cover is dropped and
  announced (see [`gateEnv`](#gateenv--the-test-gate-environment)).

- `idle.closeRoots` (256 roots at most, absolute paths, never the filesystem
  root): the repositories for which the
  [idle GC](commands.md#striart-gc-agent---close---dry-run) is **authorized to
  close a session** left unused. The repository config chooses the policy
  (`idle.action: 'close'`); terminating a process on this machine is the user's
  decision. Empty or unreadable: no automatic closing (fail closed).

These blocks widen code execution or trust, which is why they live outside the
repository. `doctor` lists `env.allow`, `gate.envAllow`, `hooks.trustedRoots`
and `network.allowInsecureHosts` among the relaxations, and the state of
`idle.closeRoots` in its "Idle GC" check.
